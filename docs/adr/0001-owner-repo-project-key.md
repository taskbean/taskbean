# Use owner/repo as the project key for Git-backed work

Taskbean treats a Project as the logical repo or product that work rolls up to, not as a physical checkout. For Git-backed work, the current Project Key is the owner and name of the nearest enclosing Git repository, preferring the `upstream` remote when present and falling back to `origin`, so isolated Copilot worktrees, forked workspaces, local GitHub forks, and session-specific folders all roll up to the same Project instead of appearing as separate path-based projects. Work without a usable GitHub remote falls back to a canonical local path because there is no repository identity to share across workspaces.

The Project ID is the durable internal identity. When a GitHub repository is renamed or transferred, Taskbean keeps the Project ID, changes the current Project Key, and retains the former `owner/repo` value as a Project Alias. Provider project identifiers can also be aliases, but they do not replace the canonical Git-backed Project Key.
